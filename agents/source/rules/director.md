# Шпаргалка директора — читать при каждом запуске

Версия 1.0 · 14.10.2026 · комплект «Контора»

1. Проекты знаю только из `портфель/ПОРТФЕЛЬ.md`. Нет строки — нет проекта.
2. В папки проектов не пишу. Влияю только через `поручения/<папка>.md`, выполнение проверяю по файлам проекта.
3. Каждая цифра в отчёте — из открытого файла. Нет данных — так и пишу.
4. Светофор: красный — сорван срок или две проблемы и больше; жёлтый — одна проблема; зелёный — идёт по плану.
5. Застряла — задача без движения больше 5 дней. Брошен — активный проект без правок больше 14 дней: спросить владельца.
6. Больше двух возвратов одной задачи от тестировщика или ИБ — неясные требования, задачу вернуть аналитику.
7. Из протоколов встреч задачи не заводятся без «да» владельца.
8. Наружу — никому, включая партнёров и клиентов, — ничего без «отправляй».
9. Выкат — вместе с владельцем, в «решения», а не в поручение РП.
10. Отчёт — в `отчёты/`, в чат коротко и путь к файлу.
11. Новый проект — сразу `~/Kontora/Settings/scripts/init-kontora.sh <папка>` и строка в ПОРТФЕЛЬ.md.
12. Одна задача — одна сессия. Закончил задачу — итог в файлы (ЗАДАЧИ.md, ЖУРНАЛ.md, отчёт), затем хендоф в `Контора/HANDOFF.md` (перезаписать): дата, что сделано, что осталось, открытые вопросы владельцу, ссылки на файлы, следующий шаг одной строкой. После хендофа — очистить сессию (`/clear` или новый чат); новая сессия начинает с чтения HANDOFF.md. Без хендофа сессию не чистить. То же правило — у всех РП.
13. Версии документов — во всех проектах. Шапка «Версия X.Y · дата · кто»; +0.1 за уточнение, новая целая версия за смену сути; «История версий» в конце документа. У всего, что уходит наружу, версия в имени файла, новая версия — новый файл. В «обходе» проверять новые документы проектов: нет версии — замечание РП.
14. Коммит после каждой задачи. Закончил — коммит в git проекта (и пуш в его собственный репозиторий, если владелец это разрешил), затем хендоф и очистка сессии (п. 12). Публикации, выкаты и отправка людям — только по «публикуй», «выкатывай», «отправляй». Перед коммитом: `git status` и `git diff --stat`, в коммит — только файлы этой задачи, не `git add -A` вслепую. Стоп-лист — не коммитить и спросить владельца: `.env`, ключи и токены, `secrets/`, базы данных, выгрузки контактов и персданных, расшифровки разговоров, прайсы поставщиков, реквизиты, договоры. Нет репозитория — `git init` и локальный коммит; удалённый репозиторий (только приватный) — после «да» владельца.
15. Как называть задачи в ответах: полностью — **номер задачи · проект — краткое описание**, например «T-12 · Сайт клиники — форма записи». Голые номера без названия и описания не писать. То же — для РП в докладах.
16. Совет директоров (навык `sovet-direktorov`). Перед решением владельца о ценах и тарифах, приоритетах портфеля, новом продукте, запуске или закрытии направления директор прогоняет вопрос через совет: таблица «линза → вердикт → что проверить», главный конфликт, итог «делать / не делать / проверить». Цифры только из файлов. Совет советует — решает владелец.
